# Choose a learning path

There is no need to learn every package before producing a useful document.
Each path below builds on a small set of working examples.

## First-time author

1. [Install an editor and compile a document](getting-started.md).
2. [Use headings, paragraphs, lists, and labels](fundamentals.md).
3. [Add mathematical notation](mathematics.md).
4. [Add a table and a referenced figure](tables-figures.md).
5. [Complete the laboratory report](projects/lab-report.md).

**Checkpoint:** you can change the report's data, rebuild it, and explain which
parts of the PDF changed.

## Student or researcher

1. Complete the first-time path, or check the [cheat sheet](cheat-sheet.md).
2. [Structure an academic argument](academic-writing.md).
3. [Manage citations with BibLaTeX and Biber](bibliography.md).
4. [Organize a multi-file thesis](research-theses.md).
5. [Practice the complete research workflow](projects/research-workflow.md).

**Checkpoint:** all citations resolve, the bibliography matches the cited
sources, and another person can compile the project from the written commands.

## Presenter or educator

1. [Understand the document structure](fundamentals.md).
2. [Build a Beamer presentation](presentations.md).
3. [Draw diagrams and plots](tikz-pgfplots.md).
4. [Choose a reusable template](templates.md).

**Checkpoint:** your slides are legible at presentation distance and their
meaning does not depend on color alone.

## Contributor or maintainer

Read [contributing](community/contributing.md), then
[maintaining the platform](community/maintaining.md). Start with an improvement
you can reproduce: a confusing explanation, a broken example, or a missing
compilation step.

**Checkpoint:** your change passes the strict website build, internal link
checks, automation tests, and all example compilations.
